# 部署说明

## 本地演示

Python 3.10+，Node 20.19+或22.12+；依赖安装、启动与CLI步骤见README。API和Worker必须在项目根目录运行。使用SQLite无须安装MySQL；数据库位于`runtime/platform.db`，WAL允许前台管理和后台写入。

2026-10-14开发验证使用Python3.13、Node24和SQLite。课程项目使用SQLite，不需要安装或配置MySQL。

## 已部署的Windows本机版本

2026-10-20完成Windows原生部署：浏览器打开`http://127.0.0.1:8010`，API文档为`http://127.0.0.1:8010/docs`。前端静态文件由API提供，后台运行单个Worker，数据库继续使用原`runtime/platform.db`。此次切换不重置数据库、不启动收费跑批。

双击项目根目录的`打开平台.cmd`会在服务未启动时按`runtime/deployment.json`记录的Python环境启动服务，再打开浏览器。双击`停止平台.cmd`会停止本项目启动记录中的API和Worker。也可手动执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start-local.ps1 -ExistingPython "<Python路径>" -SkipInstall -NoSeed
powershell -ExecutionPolicy Bypass -File .\scripts\stop-local.ps1
```

本次服务使用交付时新建并验证的虚拟环境。依赖锁文件、隔离环境完整安装与20条demo跑批的结果见`干净环境安装验证.json`、`干净环境部署验证.json`及`部署验收记录.json`。全新SQLite的验证与原项目结果数据库相互隔离。

## Docker Compose / SQLite

1. 启动Docker Desktop，确认`docker info`成功。2026-10-20本机Docker Desktop程序存在，但Linux engine未启动，故此处仅为部署步骤，Compose镜像和容器尚未在本机实测。
2. 从`.env.example`复制`.env`。默认`PROVIDER_MODE=demo`可不填云端密钥直接运行；正式调用云服务时再填模型密钥。
3. `docker compose up --build -d`。API与Worker共享SQLite文件，持久化卷挂载在`/app/runtime`。
4. 访问`http://127.0.0.1:8010`，执行本地演示；`docker compose logs worker`查看任务状态。
5. `docker compose down`停止服务但保留卷。不要在需要保留数据时使用`down -v`。

Compose只将API端口绑定至127.0.0.1，不把本地无认证管理端暴露到公网。API和Worker共享SQLite持久卷；SQLite采用WAL模式。此方案适用于课程演示的单机部署。

服务首次启动时由ORM创建表；现有表不重复创建。当前为首版建表，未来修改字段需正式迁移，不应依赖`create_all`自动升级现有列。

## 云服务接入

DeepSeek生成与Judge用OpenAI-compatible接口。Embedding独立配置；Rerank要求兼容`results[index,relevance_score]`结构。改.env后重启API与Worker；同一正式任务的服务端点/模型不允许在续跑时变化，否则创建新任务。

首先复制已审核的10题到小题集，选择1—2套配置试跑，核验召回、Judge JSON、Token用量和实际收费，再扩至六配置100题。默认C07需要重排服务；未配置重排时可选C05/C08替代构成六套，但保留重排能力的验收验证。

## 暂停与崩溃恢复验证

HTTP402余额不足会立即把整批置为暂停中，让已在途请求结束后变为已暂停。已成功结果保留，已有generation只补Judge；充值到账后再续跑，不会自动循环尝试余额不足请求。

项目采用SQLite，暂停/恢复与异常中断的操作说明不依赖MySQL。需要复制数据库时先停止API和Worker，或使用SQLite备份API。

正常暂停：任务页暂停→等待状态为已暂停→记录已成功项→点击续跑；成功项attempts不应增加。Judge失败后保留generation，再续跑只补评分。

异常中断：终止项目Worker进程→保留数据库→重启Worker；30秒租约过期后接管running任务与失联item，跳过成功项。不能保证外部API在数据库提交前的崩溃窗口不会重复计费。

## 导出和备份

`python scripts/export_reports.py RUN_ID`仅从数据库读取，输出汇总CSV、逐配置CSV、对比报告、Bad Case样本和Judge一致性报告。完整原始结果与模型调用账本保存在数据库；通过`/api/items/{id}`及`/api/runs/{id}/calls`可复查。

备份SQLite时先停止写入进程并保留数据库，或使用SQLite备份API。全量结果大文件存放在`reports/raw/`等忽略目录，仓库只保留汇总和有限样本。
