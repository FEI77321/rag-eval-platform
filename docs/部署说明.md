# 部署说明

## 本地演示

Python 3.10+，Node 20.19+或22.12+；依赖安装、启动与CLI步骤见README。API和Worker必须在项目根目录运行。使用SQLite无须安装MySQL；数据库位于`runtime/platform.db`，WAL允许前台管理和后台写入。

2026-10-14开发验证使用Python3.13、Node24和SQLite。Docker服务初始未运行，MySQL部署实测状态以验收状态和验证记录为准；不能把SQLite通过当作MySQL已通过。

## Docker Compose / MySQL 8

1. 启动Docker Desktop，确认`docker info`成功。
2. 从`.env.example`复制`.env`，填写自行设置的`MYSQL_PASSWORD`与`MYSQL_ROOT_PASSWORD`；价格与模型凭据也只写在`.env`。
3. `docker compose up --build -d`。API与Worker容器会使用MySQL，数据库名/用户名来自.env，MySQL持久卷保留数据。
4. `docker compose exec api python -m app.seed`创建演示资产。
5. `docker compose exec api python scripts/collect_sources.py`从快照入库真实语料与草稿；首次无快照时会请求官方站点。
6. 访问`http://127.0.0.1:8010`，执行小样本任务，导出报告。
7. `docker compose logs worker`检查状态；`docker compose down`停止服务但保留卷。不要在需要保留数据时使用`down -v`。

Compose只将API端口绑定至127.0.0.1，不把本地无认证管理端暴露到公网。API和Worker共享MySQL状态，所有结果不依赖容器内临时文件。

`scripts/schema_mysql.sql`由ORM定义编译，可供查看建表结构；服务首次启动执行create_all，现有表不重复创建。当前为首版建表，未来修改字段需正式迁移，不应依赖create_all自动升级现有列。

## 云服务接入

DeepSeek生成与Judge用OpenAI-compatible接口。Embedding独立配置；Rerank要求兼容`results[index,relevance_score]`结构。改.env后重启API与Worker；同一正式任务的服务端点/模型不允许在续跑时变化，否则创建新任务。

首先复制已审核的10题到小题集，选择1—2套配置试跑，核验召回、Judge JSON、Token用量和实际收费，再扩至六配置100题。默认C07需要重排服务；未配置重排时可选C05/C08替代构成六套，但保留重排能力的验收验证。

## 暂停与崩溃恢复验证

正常暂停：任务页暂停→等待状态为已暂停→记录已成功项→点击续跑；成功项attempts不应增加。Judge失败后保留generation，再续跑只补评分。

异常中断：终止项目Worker进程→保留数据库→重启Worker；30秒租约过期后接管running任务与失联item，跳过成功项。不能保证外部API在数据库提交前的崩溃窗口不会重复计费。

## 导出和备份

`python scripts/export_reports.py RUN_ID`仅从数据库读取，输出汇总CSV、逐配置CSV、对比报告、Bad Case样本和Judge一致性报告。完整原始结果与模型调用账本保存在数据库；通过`/api/items/{id}`及`/api/runs/{id}/calls`可复查。

备份SQLite时先停止写入进程并保留数据库，或使用SQLite备份API。MySQL按所用工具的安全方式导出，不把数据库密码直接写入终端命令或提交Git。全量结果大文件存放在`reports/raw/`等忽略目录，仓库只保留汇总和有限样本。
